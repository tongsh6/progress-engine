# v0.1 Pilot Validation Run

本文记录 `IV-0037: Run v0.1 pilot validation scenario` 的执行结果。它把 `docs/05-delivery/37-v0.1-pilot-validation-scenario.md` 中选定的试点从一次人工流程固化为可回归的 pytest 集成测试。

## 1. 任务选择理由

- `SDP-0036` 明确推荐下一步执行 `IV-0037`。
- 该任务验证 v0.1 的核心承诺：从模糊 intent 启动 repo-native `.progress` 状态账本，并通过 CLI 读取项目状态。
- 它复用已有 `init`、`intake`、`state show` 和 `assess` 能力，不引入 Web UI、模型 API 或 agent 编排。
- 试点能暴露状态账本导航问题；本轮自审确认 `SG-0001` 已经是 stale open gap，并在 State Delta 中关闭。

## 2. 执行流程

在临时目录执行：

```bash
PYTHONPATH=src python3 -m progress_engine init --project pilot-initial-project
PYTHONPATH=src python3 -m progress_engine intake --from examples/initial-project/intent.md
PYTHONPATH=src python3 -m progress_engine state show
PYTHONPATH=src python3 -m progress_engine assess
```

随后新增 `tests/test_pilot_validation.py`，用 pytest 在 `tmp_path` 中重复执行同一流程并断言：

- `.progress/state/project_state.yaml` 被创建。
- `.progress/artifacts/intent.md` 与试点输入一致。
- intent maturity 更新为 `seed`。
- `progress state show` 能输出 Project State 摘要。
- `progress assess` 能输出 maturity、open gaps 和 next targets 摘要。

## 3. 结果

试点执行通过，并已纳入自动化回归测试。

本轮不声称 product maturity 进入 `validated`。原因是该试点只覆盖本地 bootstrap 和只读状态观察，不覆盖 Evidence add、verify、State Delta apply/rollback 的完整写闭环。

## 4. Review 结论

代码自审发现一个状态账本问题：`SG-0001` 仍为 open，但其 desired state 已被当前仓库事实满足。继续保留它会让 `progress gaps list` 和 `progress assess` 输出过期导航。

处理方式不是在 CLI 中隐藏该 gap，而是在状态账本中通过 `SDP-0037` 关闭它，并保持 delivery maturity 为 `weak`，因为发布方案仍未形成。

关闭 `SG-0001` 后，本轮新增 `SG-0028` / `TS-0038`，把下一步完整 State Delta 写闭环切片作为结构化导航，而不是停留在自然语言后续建议。
