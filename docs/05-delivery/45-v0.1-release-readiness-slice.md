# v0.1 Release Readiness Slice

本文定义 `IV-0048: Define v0.1 release readiness slice` 的交付切片。它承接 State Delta lifecycle pilot 通过之后的缺口：仓库已经具备可运行 CLI 和本地回归验证，但还缺少面向真实试用者的安装方式、试用流程、版本边界和发布前检查清单。

## 1. 切片结论

v0.1 release readiness 的目标不是发布 SaaS 或引入自动化发布系统，而是让一个本地用户能够从仓库 clone 开始，清楚完成以下路径：

```text
clone repository
  -> prepare Python 3.11+ environment
  -> install or run CLI locally
  -> run repository checks
  -> initialize a sample project
  -> capture intent
  -> assess current project state
  -> inspect gaps, targets, interventions, evidence and deltas
```

本切片选择的 release readiness 边界是：

- 提供本地 editable install 路径。
- 保留 `PYTHONPATH=src python3 -m progress_engine ...` 作为无需安装的开发入口。
- 明确试用命令只覆盖当前已实现 CLI。
- 明确发布前必须通过仓库检查、pytest 和两个 pilot 回归。
- 明确 v0.1 不包含 Web UI、SaaS、多用户协作、模型 API 调用或外部 agent 编排。

## 2. 安装方式

v0.1 支持两种本地使用方式。

### 2.1 开发入口

```bash
git clone https://github.com/tongsh6/progress-engine.git
cd progress-engine
PYTHONPATH=src python3 -m progress_engine assess
```

该路径适合贡献者和本仓库自检，不要求 console script 已安装。

### 2.2 Editable Install

```bash
git clone https://github.com/tongsh6/progress-engine.git
cd progress-engine
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -e .
progress assess
```

该路径依赖 `pyproject.toml` 中的 package metadata 和 `progress = "progress_engine.cli:main"` console script。v0.1 发布前应至少在干净环境中 smoke test 一次。

## 3. 试用流程

用户可以在一个空目录中试用 bootstrap 流程：

```bash
mkdir /tmp/progress-engine-trial
cd /tmp/progress-engine-trial
progress init --project sample-tool
cat > intent.md <<'EOF'
I want to build a small local tool with a clear v0.1 scope.
EOF
progress intake --from intent.md
progress state show
progress assess
progress gaps list
progress target list
progress intervention list
```

用户也可以在 ProgressEngine 仓库中观察当前项目账本：

```bash
progress assess
progress state history
progress run list
progress evidence list
progress verify list
progress delta list
progress event list
```

试用流程不应要求用户配置模型 API key、启动 Web 服务或连接外部 agent。

## 4. 版本边界

v0.1 是 CLI bootstrap release，能力边界如下：

- 已实现本地 `.progress/` 账本初始化和 intent 捕获。
- 已实现 Project State、history、gap、target、intervention、run、evidence、verification、delta 和 event 的只读观察入口。
- 已实现 human-gated `delta apply`、`delta rollback` 和 `delta reject`。
- `state refresh` 只做只读 reconciliation，不写 Project State。
- Project State 只能通过 Evidence、Verification、State Delta Proposal 和 human gate 更新。

v0.1 不承诺：

- 自动生成 Gap、Target、Intervention、Evidence、Verification 或 State Delta。
- 自动调用 ChatGPT、Codex、Claude Code 或其他外部 agent。
- Web UI、SaaS、多用户协作、远程同步或数据库。
- 打包发布到 PyPI、Homebrew、Docker image 或安装器。
- 通用 YAML patch engine 或跨仓库 workspace。

## 5. 发布前检查

v0.1 release readiness run 必须记录以下命令结果：

```bash
python3 -m pytest
python3 scripts/check_repo.py
PYTHONPATH=src python3 -m progress_engine assess
PYTHONPATH=src python3 -m progress_engine state show
PYTHONPATH=src python3 -m progress_engine state history
PYTHONPATH=src python3 -m progress_engine target list
PYTHONPATH=src python3 -m progress_engine intervention list
PYTHONPATH=src python3 -m progress_engine evidence list
PYTHONPATH=src python3 -m progress_engine delta list
```

发布前还应执行一个安装 smoke test：

```bash
python3 -m venv .venv-release-smoke
. .venv-release-smoke/bin/activate
python3 -m pip install -e .
progress assess
deactivate
```

如果依赖下载、虚拟环境创建或 console script 安装失败，该失败必须作为 Evidence 记录，不能把 delivery maturity 提升到 reviewed。

## 6. Evidence Required

下一轮 release readiness run 完成后，Evidence 至少包含：

- `python3 -m pytest` 命令结果。
- `python3 scripts/check_repo.py` 命令结果。
- `progress assess`、`progress state show` 和主要 list 命令的示例输出。
- editable install smoke test 结果。
- bootstrap pilot 和 State Delta lifecycle pilot 仍在测试集中通过的说明。
- git diff 摘要，证明没有引入 Web UI、SaaS、多用户、模型 API 或外部 agent。

本切片明确不做：

- 实现打包或发布自动化

- 自动生成 Evidence、Verification 或 State Delta
- 改变 Project State write gate 规则
