# v0.1 Pilot Validation Scenario

本文定义 `IV-0036: Select v0.1 pilot validation scenario` 的产品验证切片。它只选择代表性试点场景，不实现新的 CLI 能力，也不声称 product 已 validated。

## 1. 试点选择结论

v0.1 的代表性试点选择：

```text
从一个个人开发者的模糊项目意图开始，用 ProgressEngine 本地 CLI 建立 `.progress` 状态账本，并完成一轮只读状态观察。
```

试点输入使用：

```text
examples/initial-project/intent.md
```

该 intent 描述的是一个状态驱动的 AI 软件工程系统，目标是帮助个人或小团队从模糊项目意图开始推进项目状态，避免 AI 假完成和长上下文漂移。

## 2. 选择理由

- 它直接覆盖 v0.1 的核心承诺：从模糊 intent 进入 repo-native Project State。
- 它不要求外部 API、Web UI、模型调用或真实用户访谈，适合本地可重复验证。
- 它能覆盖当前已实现 CLI：`progress init`、`progress intake`、`progress state show` 和 `progress assess`。
- 它足以暴露状态账本质量问题，例如 evidence refs、open gaps 和 next targets 是否可信。
- 它不会把试点范围扩大成完整 agent 自动执行或多项目管理。

## 3. 试点流程

在临时项目目录中执行：

```bash
PYTHONPATH=src python3 -m progress_engine init --project pilot-initial-project
PYTHONPATH=src python3 -m progress_engine intake --from /path/to/progress-engine/examples/initial-project/intent.md
PYTHONPATH=src python3 -m progress_engine state show
PYTHONPATH=src python3 -m progress_engine assess
```

期望观察：

- `.progress/state/project_state.yaml` 被创建。
- `.progress/artifacts/intent.md` 被写入。
- intent maturity 能从初始化状态推进到 `seed`。
- `state show` 能读取 Project State。
- `assess` 能输出 project、phase、maturity、open gaps 和 next targets。

## 4. 验证边界

本试点只验证：

- 本地 CLI bootstrap 能否从 intent 建账。
- Project State 是否能被读取和汇总。
- 质量门禁是否能发现账本引用漂移。

本试点不验证：

- 模型调用或外部 agent 执行。
- 自动生成 Gap / Target / Intervention。
- Evidence add、verify、delta apply 的完整写操作。
- 真实用户长期留存或商业价值。
- product maturity 从 `accepted` 升级到 `validated`。

## 5. Acceptance Criteria

| ID | Criterion |
|---|---|
| AC-PILOT-001 | 试点输入文件明确，并存在于仓库中。 |
| AC-PILOT-002 | 试点流程覆盖 `init`、`intake`、`state show` 和 `assess`。 |
| AC-PILOT-003 | 试点成功判断聚焦 Project State 和 Evidence，不依赖模型或外部服务。 |
| AC-PILOT-004 | 试点边界明确说明不验证 product validated。 |
| AC-PILOT-005 | 仓库检查和全量 pytest 仍通过。 |
