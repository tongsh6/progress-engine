# ADR-0001：v0.1 技术栈选择

## 状态

Accepted。`SDP-0003` 已在 2026-05-17 通过 human gate 并 apply，Project State 的 architecture maturity 已推进到 `accepted`。

## 背景

ProgressEngine v0.1 的产品边界已经进入 accepted 状态：第一阶段必须先证明 repo-native 的项目状态推进闭环，而不是直接扩展成完整 CLI、Web UI、SaaS、模型 API 接入或外部 agent 编排。

v0.1 实现需要优先处理本地文件、YAML / Markdown、可审查 Evidence、State Delta Proposal 和人工 gate。它的核心风险是状态协议是否可信、可追溯、可回滚，而不是性能、并发或生产部署。

## 决策

v0.1 主实现语言选择 **Python 3.11+**。

第一版 CLI 采用 stdlib-first 路径，优先使用 `argparse`。CLI 层必须保持薄封装，后续如果交互复杂度真实上升，可以迁移到 Typer 或 Click。

状态事实源保持 repo-native 文件：

- YAML：Project State、State Gap、Target State、Intervention、Evidence、State Delta Proposal、Change Event。
- Markdown：协议、Fresh Context Capsule、报告和人工审查材料。
- JSONL：append-only 的 state history 和 event log。

实现阶段引入 PyYAML 作为最小 YAML 依赖。`scripts/check_repo.py` 继续保持低依赖，并在 PyYAML 缺失时给出清晰提示或降级检查。

v0.1 不引入数据库、Web server、SaaS runtime、模型 SDK、外部 agent adapter、支付 / 权限系统或跨项目 workspace 管理。

## 决策理由

选择 Python 的原因不是“Python 永远最好”，而是它最适合当前状态边界：

- 仓库已有 `scripts/check_repo.py` 和 `src/progress_engine/` 预留目录，继续使用 Python 能减少技术栈分裂。
- v0.1 的主要工作是文件系统、YAML、Markdown、JSONL、fixture-based tests 和本地 CLI，Python 实现摩擦低。
- v0.1 明确排除 Web UI、SaaS、完整模型 API 和复杂 agent 编排，暂时用不上 TypeScript 在前端和 Web 工程上的优势。
- repo-native 状态账本需要保持 Git 可审查性，Python + 文件格式比数据库或服务端 runtime 更贴近目标。
- 当前阶段应先验证状态推进闭环，不应把二进制分发、性能或复杂 CLI UX 作为主风险。

## 后果

正向影响：

- 与当前仓库结构一致。
- 更容易快速实现和验证状态推进闭环。
- 方便读取、生成和检查 YAML / Markdown / JSONL。
- 支持 prompt-only / manual-run，不需要等待模型 API 工作。

代价：

- Python packaging 和 CLI 分发仍需在实现阶段明确。
- `argparse` 的交互体验弱于 Typer / Click。
- YAML 对象一致性必须通过 `IV-0004` 和后续实现补强。

## 备选方案

### Node.js / TypeScript

v0.1 不采用为主路径。它适合 Web、前端和强类型工具链，但当前 MVP 的主要风险在状态协议、证据验证和 repo-native 文件工作流，不在 Web 生态。

### Rust

v0.1 不采用。Rust 适合稳定后的高质量 CLI 和二进制分发，但实现成本高于当前 MVP 验证需求。

### Go

v0.1 不采用。Go 的分发体验好，但在 YAML / Markdown / 本地协议迭代上并不比 Python 更低摩擦。

### SQLite 或嵌入式数据库

v0.1 不采用。数据库会降低 Project State 和 Evidence 在 Git 中的直接可审查性。

### 完整模型 API 接入

v0.1 明确排除。当前产品边界要求先支持 prompt-only / manual-run。

## 实现边界

本 ADR 决定 v0.1 技术方向，不要求一次性实现完整 CLI。后续 implementation interventions 已按该边界逐步落地：

- `pyproject.toml` 已作为 Python package 配置引入。
- 第一批代码放在 `src/progress_engine/` 下。
- 测试放在 `tests/` 下，以 fixture-based checks 为主。
- State Delta apply 必须继续经过 gate，并保持可回滚。

## 后续推进

- `IV-0004` 已强化 docs、YAML 和 `.progress` 对象检查。
- 后续 implementation interventions 应继续保持 CLI-first、小切片、Evidence-backed 的推进方式。
